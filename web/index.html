LilyGO T-Embed CC1101 Plus · ESP32-S3

Install the lab firmware from your browser

An unofficial, Momentum-inspired Flipper-style firmware for the T-Embed CC1101 Plus, built from public source with a passive-by-default lab profile. Plug the device in, pick a build, press Install.

Experimental. This firmware has not been tested on a physical T-Embed yet. Leave the backup option ticked the first time, and skim the recovery notes before you start. Nothing here can damage the chip: its download mode is in ROM, so you can always flash again.

    Connect the T-Embed

    Plug it into this computer with a USB-C data cable, press Connect and choose the entry that appears, usually “USB JTAG/serial debug unit”.

    The device is not listed, or connecting fails
    1. Download mode: press and hold the encoder (it is the BOOT key), click the RST button on the back, then release the encoder. Press Connect again.
    2. Cable: many USB-C cables only charge. Try another one, plugged straight into the computer.
    3. Port in use: close Arduino IDE, PlatformIO, qFlipper, serial monitors and other flasher tabs.
    4. Linux: add your user to the dialout group (on some distributions uucp), then log out and in again.

    Set up the SD card
    
          
    Format a microSD card as FAT32 (LilyGO recommends SanDisk, 32 GB or smaller), extract the bundle to its root and insert it. The bundle holds IR libraries, NFC and Sub-GHz data and animations.

    Choose your TX region
    
          
    Sub-GHz transmit stays off until you pick a region in Sub-GHz → Radio Settings → TX Region. Receiving works without it. The presets limit frequency, not power or duty cycle.

    What this firmware is
    
      
    It builds on Sor3nt’s Flipper Zero ESP32 port, uses Momentum as its feature reference and is compiled with a lab profile: tools for your own equipment stay in, tools built to attack other people’s equipment are left out.
    
      
    
        
    
          
    Included
    
          
      
            
    • Sub-GHz: read, decode and save (58 remote and sensor protocols plus 25 weather stations), RAW capture, frequency analyzer, spectrum; transmit of fixed-code and RAW signals inside your chosen region
      • 
            
    • NFC (13.56 MHz): read, identify, parse and save tags
      • 
            
    • Infrared: learn, save and universal remotes
      • 
            
    • nRF24: module check and a receive-only 2.4 GHz activity view
      • 
            
    • WiFi Lab: passive network scan, join your own network
      • 
            
    • BLE Lab: passive Bluetooth LE scan
      • 
            
    • U2F security key, file archive, JavaScript apps, menu styles, asset packs
      • 
          
    
        
    
        
    
          
    Left out on purpose
    
          
      
            
    • Wi-Fi deauthentication, evil portal, handshake capture, WPS attacks, beacon spam
      • 
            
    • Sub-GHz jamming, brute force, and generating or sending rolling codes (those decode only)
      • 
            
    • NFC key attacks, cloning, emulation and writing
      • 
            
    • nRF24 jamming and MouseJack, BLE spam, BadUSB
      • 
          
    
          
    Not possible on this hardware
    
          
      
            
    • 125 kHz RFID and iButton (no reader for them on the board), 5 GHz Wi-Fi
      • 
          
    
        
    
      
    
      
    Evidence for each feature and what is still missing: feature matrix · Momentum parity · project report.
    

      
    How these builds are made
    
      
    Every file offered here is built by GitHub Actions from the commit shown next to it, with a pinned ESP-IDF v5.4.1 toolchain, and the build fails if any left-out feature is linked into the image. Before writing, this page checks each file’s SHA-256 against the build manifest; after writing, it compares the device’s own MD5 of every region with the file. Each file also carries a GitHub build-provenance attestation you can check with gh attestation verify furi_esp32.bin --repo {{REPO}}.
    
    
    

    
    
      
    Advanced
    
      
    These need a connected device (step 2).
    
      
    
        Restore a backup
        
    Writes a full 16 MB backup back to the device: one saved by this page, or made with esptool read_flash 0 0x1000000.
    
        
    
          
          
        
    
      
    
      
    
        Back up only
        
    Reads the whole flash into a file without changing anything. The device stays in download mode afterwards; press RST on the back to restart it.
    
        
      
    
      
    
        Erase the flash
        
    Leaves the device with no firmware until you install or restore one. Usually not needed: “Erase everything first” in step 3 does the same as part of an install.
    
        
      
    
      
    
        Download the files or flash with esptool
        
    Choose a build first.
    
        
    With esptool installed, from the folder with the four files:
    
        
    python -m esptool --chip esp32s3 write_flash 0x0 bootloader.bin 0x8000 partition-table.bin 0x10000 furi_esp32.bin 0xbf0000 ota_data_initial.bin
    
        
      
    
    
    

    
    
      
    Requirements and recovery
    
      
    
        
    Which browsers work?
    
        
    Chrome, Edge or Opera on Windows, macOS, Linux or ChromeOS. They support Web Serial; Firefox, Safari and phone browsers do not.
    
        
    Do I need a driver?
    
        
    No. The ESP32-S3’s built-in USB uses the standard drivers on Windows 10 and 11, macOS and Linux.
    
        
    It stopped half-way, or the device no longer starts.
    
        
    That is recoverable. Put the device in download mode (hold the encoder, click RST on the back, release the encoder), connect again and press Install, or restore your backup under Advanced.
    
        
    It starts, but the screen stays dark or it keeps restarting.
    
        
    Restore your backup, and please open an issue with the build name and the technical log. These builds have not been run on a device yet, so reports like this are exactly what is needed.
    
        
    Does it work on the original T-Embed CC1101?
    
        
    It is made for the Plus. The original model uses the same board definition, so it should run there too (the nRF24 tool will report no module), but neither has been tried yet.
    
        
    Am I allowed to use the radios?
    
        
    Use the device on equipment you own or are allowed to test, and follow the radio rules where you are. The TX region presets restrict frequency only.
